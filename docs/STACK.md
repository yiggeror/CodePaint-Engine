# 技术栈

## 通用层

| 技术 | 用途 | 当前状态 |
| --- | --- | --- |
| Python 3.10+（建议 3.11） | 时间、场景、程序控制 | 已实现 |
| NumPy | 图像缓冲、矩阵、关键帧和声音数组 | 已使用 |
| Pillow | 平面图形绘制、PNG 输出 | 可选后端 |
| FFmpeg | 音频解码、H.264 编码、最终音画合成 | 外部工具 |
| pytest | 自动回归测试 | 已配置 |
| GitHub Actions | 提交与合并时运行测试 | 已配置 |

## 已接入的程序化油画层

| 技术 | 来源与用途 |
| --- | --- |
| Numba | 对每一笔的 CPU 光栅化做 JIT 加速 |
| SciPy | 噪声与纹理滤波、关键帧插值及音频信号处理 |
| OpenCV | 笔触纹理缩放、Sobel 厚度受光、高斯柔化 |
| 自研笔刷库 | `DASH`、`DAB`、`SCUM`、`LENS`、`WASH` 五类，共 24 种纹理 |
| 三维笔触世界 | 世界坐标固定笔触、透视投影、LOD、动态网格、倒影、风场 |

第一部在 2.5D 视差场景中采用 20 种笔刷；第二部继承引擎并扩展为 24 种、添加真实三维笔触空间。共用能力主要集中在笔触光栅器、世界锚定思路、光照与渲染流程。

## 依赖安装

```bash
python -m pip install -e ".[flat]"
python -m pip install -e ".[paint]"
python -m pip install -e ".[all,dev]"
```

三个选项按需选择，无须同时运行。FFmpeg 由操作系统安装。项目依赖通过 `pyproject.toml` 管理；今后若制作可复现发布版本，可增加锁定依赖的文件。

## 不同技术方向

本仓库的公共接口不规定唯一的画面形式。未来支持方向包括：二维矢量、传统逐帧绘制、像素美术、二维骨骼、三维物理、浏览器 Canvas/WebGL、混合合成、节点式视觉效果以及其他程序化材质。

优先从实际新作品中抽象共用模块，避免为了尚未使用的画风提前设计复杂接口。

## 环境要求

- 目前的 Python 渲染主要面向离线生成，不要求 GPU。
- Numba 首次调用可能需要编译时间；后续调用复用缓存。
- 高分辨率和大量笔触可使用源项目的分段并行模式。
- 源项目音视频编码使用 `libx264`，典型输出为 1920×1080、30fps、H.264。
