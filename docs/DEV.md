# 测试与维护

## 当前维护方式

初始引擎和中文文档直接放在 `main`。日常的小修复及文档调整可以直接提交；涉及新运行时、新画风后端、大范围接口调整或替换原作算法时，建立功能分支并通过自动测试后合并。

建议遵守以下原则：

- 文件名简短、明确，文档、注释、说明优先中文；
- 任何新后端必须提供一个最小示例和至少一个测试；
- 尽量增加模块或适配器，而非修改已有作品专属数据；
- 保留使用的原始仓库、分支和提交版本；
- 记录画面生成的随机种子与版本以保持可重现性。

## 自动测试

```bash
python -m pip install -e ".[all,dev]"
python -m pytest -q
```

GitHub Actions 工作流位于 `.github/workflows/test.yml`，在推送 `main` 及提交拉取请求时运行。

## 冒烟检查

```bash
python examples/flat.py
python examples/paint.py
python examples/flat.py --video
python examples/paint.py --video
```

检查 `out/` 内图像和短视频，确认画面确实发生运动、编码正确且首尾无意外跳变。输出目录已经加入 `.gitignore`。

## 升级规则

1. 保留原功能对应的测试或添加输出对比。
2. 画面后端接口变化时同步更新 `DESIGN.md` 和示例。
3. 将与某一作品强绑定的场景实现留在该作品内。
4. 对性能优化记录测试条件、尺寸、帧数及耗时。
5. 统一检查输出格式与资源来源，长期保留可复现的构建命令。

## 跨语言扩展

浏览器动画可新建 `web/` 运行时，参考当前 `Scene → Backend → RGB/画布` 的设计。不同语言的实现不必共用相同的 Python 数据结构，但要遵循统一的“时间、场景、渲染、声音、输出”职责分离。
