# 架构

## 一、整体数据流

```text
时间轴 / 速度映射
       ↓
场景 sample(t)
       ↓
场景数据（由项目自定义）
       ↓
渲染后端 draw(data, config)
       ↓
RGB 帧（uint8，H×W×3）
       ├── 静帧预览：PNG
       └── 连续帧：FFmpeg → H.264 视频
                                + 处理后的音轨 → 完整成片
```

`Engine` 只调度时间与后端，不把画风、镜头类型、世界坐标或某一种物体格式写死。

## 二、引擎接口

### Config

`Config(width, height, fps, duration)` 定义尺寸、帧率、时长。帧总数由 `count` 自动计算。

### Scene

`sample(t)` 根据秒数返回当前帧的数据。返回值由画面后端约定：平面后端使用 `FlatFrame`，笔触后端使用 `Brush` 列表或列式数据。

### Backend

`draw(data, config)` 返回 `uint8`、三通道、RGB、指定尺寸的 NumPy 数组。

### Engine

`Engine(config, scene, backend)` 提供三个入口：

- `at(t)`：指定秒数生成一帧；
- `frame(index)`：按整数帧号生成图像；
- `frames(start, stop)`：产生一个连续帧段，结束号不包含在内。

项目只要实现 `Scene` 与 `Backend` 两个接口，即可接入输出、时间采样和测试基础设施。

## 三、时间与镜头

`time.py` 提供 `Key`、`sample`、`TimeWarp`。关键帧支持标量及同维向量，时间变速用于单镜头中不同段落的节奏调整。

`camera.py` 提供：

- `Camera2D`：二维视差投影，适合多平面、剪纸、平面画卷等；
- `Camera3D`：三维透视投影，适合立体空间中的粒子、笔触或其他物体。

画面相机可替换，不要求所有项目都建立三维世界。

## 四、已接入的笔触系统

`paint/engine.py` 源自 Rainroji《Berceuse》，支持 24 种程序化笔刷，统一绘制笔触颜色和厚度，模拟画布纹理、浮雕受光及轻微泛光。

`paint/world3.py` 源自第二部的三维笔触核心，主要结构为：

- `Path`：三维相机运动路径；
- `Env`：每一帧的相机、风、光照与当前状态；
- `SB`、`Group`：静态笔触组；
- `Field`：通过确定性哈希网格，在相机周围按需生成水面、草地等笔触；
- `shade`、`compose`：三维笔触投影、细节层级、光照、倒影和合成。

它是当前的成熟风格模块。新动画可以调用该模块，也可以编写完全不同的画面后端。

### 笔触后端数据约定

`Paint` 的简单入口为 `Brush` 列表：`x, y, length, width, rgb, angle, alpha, sprite, height, order`。

`rgb` 为 0 到 1 的浮点颜色，坐标和笔触尺寸采用 1920×1080 的设计空间。该后端当前的目标输出宽高比为 16:9，最终输出尺寸由 `Config` 控制。

三维入口由 `world3.compose` 输出 `x, y, ang, L, W, spr, rgb, a, hb` 等数组，再传入 `Paint`。项目负责组织场景组、动态角色和光照关键帧。

## 五、如何接入新风格

例如需要像素或水墨：

1. 在 `src/anim/backends/` 添加一个后端；
2. 实现 `draw(data, config)`；
3. 设计对应的场景数据，不必沿用 `Brush`；
4. 编写最小示例与测试；
5. 复用时间轴、相机、输出与音频层。

实时 WebGL、浏览器交互、多边形三维渲染与其他语言运行时可以采用独立目录和独立后端，遵循相同的时间与场景契约，不强迫共享 Python 渲染实现。

## 六、约定

- 内部颜色输出使用 RGB、`uint8`；音频处理用 48kHz 双声道浮点采样。
- 独立帧按时间求值，避免逐帧累积状态造成的片段渲染不一致。
- 随机画面元素固定种子，动态变化由世界位置、角色状态和时间决定。
- 画风后端彼此独立；共享层不进口某一个具体画风。
- 输入、后端参数以及原始素材来源应随作品记录，便于重建与复查。
